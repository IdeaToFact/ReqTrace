# Security Policy & Offline Assurance (`SECURITY.md`)

ReqTrace is designed for high-assurance engineering, aerospace, defense, and medical environments where source specifications and test suites must remain under the organization's strict physical and operational control.

## 2. Zero-Egress Air-Gap Architecture & Web Cockpit Security

ReqTrace Community Edition is architected as an **offline-first CLI, local web cockpit (`reqtrace ui`), and reporting tool** with zero remote telemetry:

- **No Remote Telemetry**: ReqTrace contains zero phone-home mechanisms, crash reporters, analytics beacons, or remote tracking scripts.
- **Local In-Process Execution**: All requirements parsing, test AST inspection, fuzzy windowing, and HTML report rendering execute purely in-process on the local host without initiating outbound network connections.
- **Air-Gapped Standalone Deliverables**: HTML reports generated by `reqtrace report` (and `ExportManager`) are 100% self-contained single-file documents with inlined CSS, SVGs, and JavaScript. No external CDNs (such as unpkg, cdnjs, or Google Fonts) are queried.
- **Automated Air-Gap Guard**: ReqTrace test suites (`tests/test_airgap_egress.py`) include an automated socket and HTTP egress assertion test verifying that core CLI commands execute without opening external socket connections.
- **Local Web Cockpit (`reqtrace ui`) Hardening**:
  - **Anti-DNS Rebinding & CSRF**: `LocalhostSecurityMiddleware` strictly validates `Host`, `Origin`, and `Referer` headers on requests.
  - **Authentication & Session Isolation**: Single-use launch tickets exchange for port-scoped `HttpOnly`, `SameSite=Strict` session cookies (`reqtrace_session_<port>`). On-demand tickets via `reqtrace ticket` authenticate against an OS-local `0600` runtime secret.
  - **Strict CSP & Upload Bounds**: Zero inline scripts or styles (`style-src 'self'`, `script-src 'self'`) and a 25MB ingestion safety ceiling on uploads.
  - **Network Binding Warning**: By default `reqtrace ui` binds to `127.0.0.1`. Passing `--host 0.0.0.0` (e.g., inside Docker containers) must only be used behind isolated container bridge port-mappings or an authenticated TLS reverse proxy inside a trusted enclave—never expose `reqtrace ui` directly to untrusted LAN or WAN interfaces.

### What Automated Air-Gap Guards Cover vs. Do Not Cover
> [!IMPORTANT]
> - **What They Cover**: `tests/test_airgap_egress.py` verifies that core ReqTrace Python CLI pipelines do not open outbound sockets or HTTP requests during execution.
> - **What They Do Not Cover**: Python-level test guards do not monitor OS background services, container daemons, initial package/container installation (`pip install`, `docker build`), or optional `FastEmbed` model weight downloads if weights are not pre-staged via `FASTEMBED_CACHE_PATH`.
> - **True Air-Gap Enforcement**: For classified or high-security enclaves, run ReqTrace on physically disconnected hardware or enforce `docker run --network none` and host firewall rules.

## 3. Threat Model & Hostile Input Defenses

ReqTrace ingests untrusted specifications, test files, and reports from external vendors. The following defenses are enforced:

1. **XML / ReqIF Entity Expansion (Billion Laughs & DTD Attacks)**:
   - ReqIF XML parsing is strictly handled through `defusedxml.ElementTree`.
   - External DTD resolution and entity expansion are explicitly disabled.
2. **Archive Decompression & File Size Guards**:
   - Word (`.docx`) specifications are parsed offline via `python-docx`. In the web UI ingestion endpoints, uploads are bounded to a 25MB maximum payload size (`.xlsx` ingestion is not supported in Community Edition, and nested zip-bomb decompression ratio limits are not yet enforced in the CLI parser).
3. **PDF Parsing Adapter Boundary (`pypdfium2`)**:
   - `pypdfium2` (Apache-2.0 / BSD-3-Clause) is declared in `pyproject.toml` as the clean-room permissive PDF adapter, though active PDF ingestion is not yet imported or wired into `reqtrace/` in `v0.2.0` (and no OS/subprocess memory-limit sandboxing is implemented for PDF parsing yet).
4. **Cross-Site Scripting (XSS) & HTML Report Injection**:
   - Specification text, requirement titles, and test docstrings often contain raw code, HTML entities, or XML tags.
   - All requirement attributes and reviewer comments are strictly escaped with `html.escape()` prior to injection into the standalone HTML report template.
5. **Tamper-Evident Review Store (Community Boundary)**:
   - The human review overlay (`.reqtrace/reviews.jsonl`) is managed as an append-only event stream.
   - When tracked under Git, commit hashes provide tamper-evident historical auditability. However, Community Edition performs **no** cryptographic PKI signing, hardware-backed attestation, or WORM immutability enforcement on `.reqtrace/reviews.jsonl` (Enterprise Edition provides cryptographic manifests and signed audit trails).

## 4. Dependency Security & Clean-Room Governance

- **Permissive Clean-Room Dependency Policy**: Direct dependencies declared in `pyproject.toml` are restricted to vetted permissive licenses (MIT, Apache-2.0, BSD, PSF) to prevent upstream GPL/AGPL contamination (`tests/test_license_guardrails.py`).
- **Vulnerability Auditing & Dependency Hygiene**: Dependency updates and advisory reviews (NVD / GitHub Advisory Database) are performed on a **best-effort, release-driven basis**—automated monthly NVD scanning is not yet configured in `.github/workflows/reqtrace_audit.yml`. Before building commercial packages, cut wheels from a clean virtual environment built strictly from `pyproject.toml` and verify with `pip-licenses`.
- **Software Bill of Materials (SBOM) & Release Signing (Roadmap)**: Automated CycloneDX/SPDX SBOM generation and GPG/Sigstore commit and wheel signing are **not yet automated** in `.github/workflows/reqtrace_audit.yml` and are planned for future release automation.

## 5. Reporting a Vulnerability & Coordinated Disclosure

If you discover a security vulnerability or defect in ReqTrace, please report it through private, responsible disclosure.

### Preferred Reporting Channels:
1. **GitHub Private Vulnerability Reporting**: Open a confidential security advisory on GitHub under `Security -> Report a vulnerability`.
2. **Email**: Send details to `security@ideatofact.com` (to request a verified PGP public key prior to sending sensitive details, email `security@ideatofact.com` first or use GitHub Private Vulnerability Reporting).

### Best-Effort Coordinated Disclosure Targets (No SLA):
For Community Edition, the timelines below are **best-effort targets** without contractual Service Level Agreements (guaranteed response SLAs are available exclusively under Commercial Pro and Enterprise agreements):
- **Initial Acknowledgment**: Target within 48 hours.
- **Triage & Impact Assessment**: Target within 5 business days.
- **Fix & Advisory Release**: Target coordination within a standard 90-day responsible disclosure window (or earlier upon mutual agreement).

### Safe Harbor:
Idea To Fact LLC will not pursue legal action or report to law enforcement any security researchers who discover and report vulnerabilities in good faith, provided that they:
- Make a good-faith effort to avoid privacy violations, data destruction, and service interruption.
- Give us reasonable time to remediate the vulnerability prior to public disclosure.
- Do not exploit vulnerabilities beyond the minimum necessary proof of concept.
